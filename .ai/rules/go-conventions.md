# Go Conventions

## Tech Stack
Go 1.26 · Gin · PostgreSQL 15 · `lib/pq` (raw SQL, no ORM) · `golang-migrate` · `golang-jwt/jwt/v5` · Zap · Testify · `go-sqlmock` (repository unit tests) · Mockery v2 · `google/uuid` · `oklog/ulid` · Prometheus client · swaggo (`docs/swagger.yaml` is embedded and served).

## ID Types
- `google/uuid` for all entity IDs (`internal/pkg/id`, `Generator.NewUUID()`). Customer, user and vehicle IDs are `VARCHAR(36)` UUIDs.
- `Generator.NewULID()` exists but no entity of this service uses it.

## Monetary Values
This service has no monetary values (`shopspring/decimal` is not in `go.mod`). If one is added: use `decimal.Decimal`, never `float64`/`float32`, and store as `NUMERIC(10,2)`.

## No Framework Leakage
- Domain structs: no imports from `gin` or `lib/pq`. Note: `internal/auth/domain` imports Zap (logging) and `x/crypto/bcrypt`.
- Services: depend only on domain interfaces, `uow` and `id`.
- Gin is confined to `internal/app/` (routing, middleware, container).

## Mock Generation
Mocks live next to their interfaces, in `internal/<domain>/interfaces/mocks/`, and in `internal/pkg/uow/mocks/`. They are generated by `//go:generate` directives on the interface files:
```go
//go:generate go run github.com/vektra/mockery/v2@latest --name=CustomerRepository --with-expecter
```
Run `make mockgen` (`go generate ./...`) to regenerate. Never edit generated mock files manually. Mocks are excluded from the coverage gate.

## Error Patterns
- Domain errors: `var ErrXxx = errors.New("...")` in the domain package (`internal/<domain>/domain/*_errors.go`).
- Services return domain errors (or wrap them with `%w`).
- `internal/pkg/web.Error()` maps them to HTTP codes with `errors.Is` / `Unwrap` (not a type switch). Validation sentinels answer `400` with `errors`; the others answer `error`. See `api.md`.
- Never expose internal error details in HTTP responses: 5xx and infrastructure conflicts are logged, the client gets a fixed message.

## In-Memory Implementations
Each domain repository has a Postgres implementation and an in-memory one, in `internal/<domain>/repository/`:
- `auth`: `in_memory.go`, `postgres.go`
- `customer`: `customers_in_memory.go`, `customers_postgres.go`
- `vehicle`: `vehicles_in_memory.go`, `vehicles_postgres.go`

The in-memory variant is used only by unit tests (`NewInMemory()`).

## Configuration
All env vars are read through `internal/pkg/env` (`GetString`, `GetInt`, `GetTimeDuration`) with defaults. The list of variables and defaults is in `README.md` ("Configuration"). Makefile reads `.env` and exports it.
