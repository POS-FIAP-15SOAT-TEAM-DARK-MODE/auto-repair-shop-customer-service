# Testing

## Coverage Thresholds
- Critical domains (authentication, customers): **90% minimum**. Global gate: **80%** (CI `coverage` job).
- All other domains: **80% minimum**.

## Commands
```bash
make test        # all tests with race detector (LOG_LEVEL=PANIC suppresses noise)
make coverage    # generate coverage.out and open HTML report
go test ./internal/domain/... -run TestXxx -v
go test ./internal/services/customer/... -v --race
```

## Unit Tests — In-Memory Implementations
- Repositories: each domain has `in_memory.go` in `infra/repository/<domain>/`.
- UoW: use `infra/db/in_memory` for service-layer tests.
- Mocks: generated by Mockery v2 in `domain/mocks/`, used for interface boundaries.

Pattern:
```go
// Arrange
repo := inmemory.NewCustomerRepository()
uow  := inmemory.NewUoW()
svc  := customer.NewService(uow, repo)
// Act
result, err := svc.Create(ctx, input)
// Assert
assert.NoError(t, err)
```

## Integration Tests
- Use a real test PostgreSQL DB.
- Each test rolls back after completion — never leaves persistent state.
- Located in `internal/infra/repository/*/` and HTTP flow test files.

## Test Structure Rules
- Arrange / Act / Assert; tests must be fully independent.
- Naming: `Test<Unit>_<Condition>_<ExpectedOutcome>`.
- Group with sub-tests (`t.Run`).
- Never share mutable state between tests.

## What to Cover
| Domain | Critical cases |
|---|---|
| Login | Valid credentials, wrong password, unknown e-mail, empty payload |
| Internal routes | 200, 404, 401 with missing or wrong `X-Internal-Token` |
| CPF / CNPJ / plate | Valid, invalid format, invalid check digits, edge cases |
| Lambda compatibility | Literal login-lambda queries as `lambda_auth_ro`; write denied (`lambda_compat_test.go`) |
| RBAC | 403 for out-of-scope roles, 401 for missing JWT |
| Customer lifecycle | Create → User auto-created; Delete → User deleted |
