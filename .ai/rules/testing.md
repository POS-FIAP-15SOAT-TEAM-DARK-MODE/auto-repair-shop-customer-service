# Testing

## Coverage Thresholds
- Gate enforced by the CI `coverage` job: **80%** total, **excluding `/mocks/`** paths.
- Target per package for authentication and customers: 90%. Not enforced by CI. Current measure is in `README.md` (`internal/auth/repository` is below it, 70%).

## Commands
```bash
make test        # all tests with race detector (LOG_LEVEL=PANIC suppresses noise)
make coverage    # generate coverage.out and open HTML report
go test -tags=integration ./internal/integration/... -v   # needs Postgres (see make test-integration)
go test ./internal/domain/... -run TestXxx -v
go test ./internal/services/customer/... -v --race
```

## Unit Tests — In-Memory Implementations
- Repositories: each domain has an in-memory variant (`NewInMemory()`), see `go-conventions.md`.
- UoW: use `uow.NewInMemoryUoW()` (`internal/pkg/uow`) for service-layer tests.
- Mocks: generated by Mockery v2 in `internal/<domain>/interfaces/mocks/` and `internal/pkg/uow/mocks/`, used for interface boundaries. Not counted in coverage.

Pattern (customer service tests):
```go
// Arrange
repo := customerRepo.NewInMemory()
svc  := customer.NewService(uow.NewInMemoryUoW(), repo, authRepo.NewInMemory(), orders)
// Act
result, err := svc.Create(ctx, input)
// Assert
assert.NoError(t, err)
```

## Integration Tests
- Build tag `integration`; suite in `internal/integration/` runs HTTP flows against a real PostgreSQL with the migrations applied (CI service container).
- Repository SQL is also covered by `*_postgres_test.go` with `go-sqlmock` (no real DB).
- Isolation is by unique data per test (generated CPF, e-mail, phone), not by rollback: tests do not roll back their rows.

## Test Structure Rules
- Arrange / Act / Assert; tests must be fully independent.
- Naming: prefer `Test<Unit>_<Condition>_<ExpectedOutcome>` for new tests (older tests use shorter names).
- Group with sub-tests (`t.Run`).
- Never share mutable state between tests.

## What to Cover
| Domain | Critical cases |
|---|---|
| Login | Valid credentials, wrong password, unknown e-mail, empty payload |
| Internal routes | 200, 404, 401 with missing or wrong `X-Internal-Token` |
| CPF / CNPJ / plate | Valid, invalid format, invalid check digits, edge cases |
| Lambda compatibility | Literal login-lambda queries as `lambda_auth_ro`; write denied (`lambda_compat_test.go`) |
| RBAC | 403 for out-of-scope roles, 401 for missing JWT |
| Customer lifecycle | Create → User auto-created; Delete → User deleted |
